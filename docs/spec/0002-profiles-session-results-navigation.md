# 規格書：簡介、場次結果與導覽（第二批）

> 狀態：待實作（`ready-for-agent`）｜ 語彙依據：[CONTEXT.md](../../CONTEXT.md) ｜ 承接：[規格書 0001](0001-f1-paddock.md) ｜ 決策依據：[ADR-0001](../adr/0001-hybrid-snapshot-data-strategy.md)、[ADR-0003](../adr/0003-image-policy.md)、[ADR-0004](../adr/0004-auto-rolling-season-with-archive.md)

## Problem Statement

網站上線兩天後，實際使用暴露出幾個「看得到骨架、找不到血肉」的缺口：

- 一個 Race Weekend 有五到六個 Session，但網站只給正賽的 Result。週五晚上打開單站頁，看不到剛結束的 FP2 誰最快；週六排位賽結束後也只能等週日。
- Team、Driver、Circuit 頁面只有數字（積分、彎道數、圈數），沒有一段話告訴剛入坑的人「這支車隊是誰、這位車手從哪來、這條賽道為什麼有名」。
- 從首頁點進一位 Driver 之後，畫面上沒有任何東西告訴使用者「我現在在站內的哪裡」，回上一層只能靠瀏覽器的返回鍵或頂欄。
- 瀏覽器分頁與手機主畫面上，網站沒有自己的圖示，在一排分頁裡認不出來。

## Solution

在既有的資料管線與頁面上補四件事，不改變網站的形狀：

1. **每個 Session 都有 Result**。單站頁改為分頁籤（正賽｜排位賽｜FP3｜FP2｜FP1，衝刺賽週末依資料組成），預設停在最新已結束的場次；練習賽與排位賽以 Best Lap 與 Gap 排名。
2. **Team、Driver、Circuit 各有 Profile**。手寫的繁中簡介文字，加上少量結構化欄位：Driver 的年齡、國籍、出道年與第幾季；Team 的總部與動力單元供應商；Circuit 的賽道長度。Profile 是可選的，缺少時不顯示區塊。
3. **內頁有 Breadcrumb**。頂欄下方顯示「首頁 / 車手 / 安東內利」，前段可點、最後一段為目前頁面。
4. **網站有自己的 Favicon**。F1 紅底、白色「P」字標，SVG 為主、附 iOS 主畫面用的 PNG。

## User Stories

### 場次結果

1. 作為一個觀眾，我想在單站頁看到 FP1、FP2、FP3 的結果，這樣週五、週六就有東西可看，不必等到週日。
2. 作為一個觀眾，我想看到排位賽每位車手的 Q1、Q2、Q3 時間，這樣我知道誰在哪一節被淘汰。
3. 作為一個觀眾，我想看到練習賽與排位賽每位車手的 Best Lap 與 Gap，這樣我能判斷誰的單圈速度好。
4. 作為一個觀眾，我想在單站頁用分頁籤切換各個 Session 的 Result，這樣一頁不會長到拉不完。
5. 作為一個觀眾，我想打開單站頁時預設停在**最新已結束的場次**，這樣賽事週末當中每天打開都直接看到新東西。
6. 作為一個觀眾，我想在衝刺賽週末看到衝刺排位與衝刺賽的 Result 也出現在分頁籤中，且沒有 FP2／FP3 的空籤，這樣場次組成永遠與實際一致。
7. 作為一個觀眾，我想看到尚未舉行的場次籤是停用狀態並標示開始時間，這樣我知道它還沒發生而不是資料壞了。
8. 作為一個觀眾，我想在練習賽結果看到未跑出計時圈的車手標示為「無成績」而非空白，這樣我不會誤以為畫面有缺漏。
9. 作為一個觀眾，我想在排位賽結果看到被淘汰在 Q1 的車手只有 Q1 欄有值、其餘欄以「—」呈現，這樣一眼看出淘汰節次。
10. 作為一個觀眾，我想在每個 Session 的 Result 看到車手的 Team 代表色條與中英文名，與正賽賽果一致，這樣切換分頁時視覺不跳。
11. 作為一個觀眾，我想在手機上看到練習賽結果只保留名次、車手、Best Lap，其餘收進可展開列，這樣窄螢幕不會橫向捲動。
12. 作為一個觀眾，我想在首頁的場次面板上看到已結束的練習賽或排位賽列標出第一名，這樣不進單站頁也知道誰最快。
13. 作為一個觀眾，我想在任何一站（包含本季開頭）都看到完整的 Session Result，這樣回頭比較各站時不會有斷層。

### Driver Profile

14. 作為一個觀眾，我想在車手頁看到一段繁中簡介，這樣我知道這位車手的背景與風格。
15. 作為一個觀眾，我想看到車手的年齡與生日，這樣我知道他是新秀還是老將。
16. 作為一個觀眾，我想看到車手的國籍以中文與國旗呈現，這樣我不必翻譯「Italian」。
17. 作為一個觀眾，我想看到車手「F1 第 N 季 · YYYY 出道」，這樣我知道他的資歷，而且跨年後自動變成第 N+1 季。
18. 作為一個觀眾，我想看到車手的車號與 Team 一起放在簡介卡上，這樣一張卡就是他的名片。
19. 作為一個觀眾，我想在本季首次出賽的新秀看到「第 1 季 · 本季出道」，這樣資歷欄不會出現「第 1 季 · 2026 出道」這種贅述。
20. 作為一個維護者，我想在某位車手還沒有簡介文字時，車手頁只隱藏簡介段落、結構化欄位照常顯示，這樣缺一段文字不會讓整張卡消失。

### Team Profile

21. 作為一個觀眾，我想在車隊頁看到一段繁中簡介，這樣我知道這支車隊的來歷。
22. 作為一個觀眾，我想看到車隊的總部所在地，這樣我知道它是英國隊還是義大利隊。
23. 作為一個觀眾，我想看到車隊的動力單元供應商，這樣我理解 2026 新規則下誰用誰的引擎。
24. 作為一個觀眾，我想看到 Audi 與 Cadillac 這種新車隊的簡介說明它們的出身，這樣我不會把它們和改名前的隊伍搞混。

### Circuit Profile

25. 作為一個觀眾，我想在賽道頁看到一段繁中簡介，這樣我知道這條賽道的特色。
26. 作為一個觀眾，我想看到賽道長度（公里，小數三位），與既有的彎道數、圈數、單圈紀錄排在一起，這樣賽道規格一目瞭然。
27. 作為一個觀眾，我想看到賽道長度乘以圈數的正賽總里程，這樣我知道這場比賽跑多遠。

### Profile 的維護

28. 作為一個維護者，我想把所有 Profile 文字放在一個檔案裡，這樣我能一次通讀、審閱語氣一致。
29. 作為一個維護者，我想在本季有實體缺少 Profile 時收到測試**警告**而非失敗，這樣換季時新車手不會擋住自動部署。
30. 作為一個維護者，我想在 Profile 指向不存在的實體 ID 時測試**失敗**，這樣打錯 ID 會立刻被抓到。
31. 作為一個觀眾，我想看到 Profile 文字裡的專有名詞遵守既有譯名（麥拉倫、賓士…），這樣全站說法一致。

### Breadcrumb

32. 作為一個觀眾，我想在每個內頁的頂欄下方看到「首頁 / 車手 / 安東內利」，這樣我知道我在站內的哪裡。
33. 作為一個觀眾，我想點 Breadcrumb 的前段回到上一層列表，這樣我不必用瀏覽器返回。
34. 作為一個觀眾，我想 Breadcrumb 的最後一段是目前頁面、不可點，這樣我不會點了沒反應。
35. 作為一個觀眾，我想 Breadcrumb 的最後一段是中文譯名，沒有譯名時是英文名，這樣它短而可讀。
36. 作為一個觀眾，我想在首頁**不**看到 Breadcrumb，這樣首頁開頭仍是乾淨的倒數。
37. 作為一個觀眾，我想在單站頁看到「首頁 / 賽程 / 西班牙大獎賽」，這樣站次也有清楚的上層。
38. 作為一個觀眾，我想在列表頁（車隊、車手、賽道、賽程）看到「首頁 / 車手」兩段，這樣層級一致。
39. 作為一個使用螢幕閱讀器的觀眾，我想 Breadcrumb 是一個標示為「導覽」的 `nav`、目前頁面帶 `aria-current`，這樣輔助工具能正確朗讀。
40. 作為一個手機使用者，我想 Breadcrumb 在窄螢幕上不換行、過長時尾端截斷，這樣它永遠只占一列。

### Favicon

41. 作為一個觀眾，我想在瀏覽器分頁看到 F1 紅底白色「P」的圖示，這樣我在一排分頁裡認得出這個網站。
42. 作為一個 iOS 使用者，我想把網站加到主畫面時有清晰的圖示而不是截圖，這樣它看起來像個 app。
43. 作為一個觀眾，我想圖示在深色與淺色的分頁列上都清楚，這樣不同瀏覽器主題都認得出。
44. 作為一個觀眾，我想在 404 頁與所有預產生的路由都看到同一個圖示，這樣任何入口都一致。

## Implementation Decisions

### Session Result 的資料來源與形狀

- **練習賽 Result 來自 OpenF1** 的 session_result 端點（已實測：每場次回傳名次、車號、圈數、Best Lap 秒數、Gap 秒數、DNF／DNS／DSQ 旗標）。Jolpica 沒有練習賽資料。排位賽維持用 Jolpica（已在快照中，含 Q1／Q2／Q3）；OpenF1 的排位賽結果不採用，避免同一場次兩個來源。
- 取得場次對照：每季一次請求 OpenF1 的 sessions 端點取得全季 session_key，依 **Round 與場次種類**對到 Snapshot 的 Session。以日期比對作為備援，不以場次名稱字串比對（OpenF1 的 `session_name` 在衝刺週末命名不穩定）。
- **車手對應用 OpenF1 車號 ↔ 縮寫表**（抓取時已取得），再以縮寫對回 Jolpica 的 Driver。**不可用 Jolpica 的 `permanentNumber`**：Verstappen 在 Jolpica 是 33、賽場用 1。對不到縮寫的車號（例如練習賽的青年車手）保留車號、Driver 為 null，畫面顯示車號與「未登錄車手」。
- Snapshot 的 Session 新增可選的 `result`：練習賽為 `{ driverId, position, bestLapMs | null, gapMs | null, laps }` 陣列；排位賽沿用既有 QualifyingResult；正賽與衝刺賽沿用既有 RaceResult。時間一律以**毫秒整數**存，不存字串，格式化留給畫面。
- **全季所有場次都存**（使用者決策）。練習賽 Result 從主要資料 chunk 拆出，只在單站頁載入；首頁載入量不變。
- 抓取失敗（OpenF1 401、逾時）時**該場次的 result 保留上一份快照的值**，與既有的代表色／照片 carry-forward 同一套機制；沒有舊值則為 null，畫面顯示「結果尚未取得」。
- View Model 的 SessionView 新增 `resultView`：已把 driverId 解析成 Driver／Team、加上 Gap 的顯示用文字（第一名為空、其餘為 `+0.442`）與「無成績」旗標。**Best Lap 與 Gap 的格式化（`1:23.008`）在 View Model 完成**，元件不做時間運算，與既有 `msUntilRace` 的原則相同。

### 單站頁的分頁籤

- 籤的順序固定為 **正賽 → 排位賽 → FP3 → FP2 → FP1**（衝刺週末為 正賽 → 排位賽 → 衝刺賽 → 衝刺排位 → FP1），只列出資料裡存在的場次。
- **預設籤 = 最新已結束的場次**，由 View Model 決定（`weekend.latestFinishedSession`），元件不自己找。全部未開始時預設第一個籤並停用所有籤、顯示開始時間。
- 籤是可及性正確的 tab 元件（`role="tablist"`／`tab`／`tabpanel`、方向鍵切換）。籤的切換**不改變網址**——一站一個網址，符合 ADR-0002 的預產生路由清單，不新增路由型態。
- 首頁場次面板：已結束的練習賽與排位賽列在時間旁加上第一名車手縮寫與 Best Lap，不加新列。

### Profile

- **手寫、進 repo、可選**（使用者決策）。三張表（Team／Driver／Circuit）放在同一個 Profile 資料檔，以實體 ID 為鍵，與既有譯名表分開——譯名表是「名字」，Profile 是「內容」，維護節奏不同。
- Driver Profile 的結構化欄位：
  - **年齡與生日**：來自 Jolpica `dateOfBirth`（新增進 Snapshot 的 DriverRef）。年齡在 View Model 用注入的「現在時間」計算，畫面顯示「20 歲」並標生日。
  - **國籍中文**：新增國籍（Jolpica 英文 demonym）→ 中文對照，與國旗對照表同處維護。本季有車手國籍缺對照時測試失敗（這是名字級的資料，與譯名表同等級）。
  - **出道年**：抓取時對每位車手請求 Jolpica「第一筆正賽 Result」（`results?limit=1`），取其 season。**不可用 `/drivers/{id}/seasons`**：已實測 Antonelli 回傳 2024（僅出賽 FP1）而非 2025，會算錯資歷。存進 Snapshot 的 DriverRef 為 `debutSeason`。抓取失敗時 carry-forward 舊值。
  - **第 N 季**：`當前季 − debutSeason + 1`，在 View Model 計算；等於 1 時顯示「本季出道」。
- Team Profile 的結構化欄位：總部所在地、動力單元供應商——皆手寫，與簡介文字同表。
- Circuit Profile 的結構化欄位：**賽道長度**取自已 vendored 的 GeoJSON metadata（`lengthMetres`），顯示為公里、小數三位；**正賽總里程** = 長度 × 圈數，在 View Model 計算。
- Profile 文字的**語氣規範**：第三人稱、每則 2–4 句、不寫會過期的數字（例如「目前積分榜第三」），可寫穩定事實（首次奪冠年、賽道啟用年）。專有名詞遵守譯名表。
- 頁面上的區塊標題一律為「簡介」。缺文字時整段隱藏；缺結構化欄位時該列隱藏，不顯示「—」。

### Breadcrumb

- Breadcrumb 由**路由層**產生：每個路由對應一條「段落鏈」，段落的顯示文字由 View Model 提供的譯名解析。**不由各頁面自行拼字串**，避免十個頁面各寫一次。
- 段落規則：首頁 → 列表頁（車隊／車手／賽道／賽程）→ 實體頁（中文譯名，缺則英文）。單站頁的實體段為大獎賽譯名。
- 元件為 `nav aria-label="路徑導覽"` + 有序列表，最後一段帶 `aria-current="page"`。首頁不渲染。
- 窄螢幕 `white-space: nowrap` + `text-overflow: ellipsis`，保證單列。
- 分隔符為「/」，不用「›」——與使用者範例一致，且中文字型下「/」的字重最接近正文。

### Favicon

- `favicon.svg` 為主要圖示（現代瀏覽器）；`apple-touch-icon.png` 180×180（iOS 不吃 SVG）；`favicon.ico` 32×32 為舊版備援。三者由**同一份 SVG 原稿**在建置前產生，不手工維護多份。
- 圖形：F1 紅 `#e10600` 圓角方底、白色粗體「P」，右側一道斜切線做出速度感。**不使用 F1 官方字型或商標**（ADR-0003 的精神）。
- 圖示放在 `public/`，隨 Vite base 路徑輸出；預產生的每個路由 HTML 與 404.html 自然帶同一組 `<link rel="icon">`。

### 快照大小與 chunk

- 練習賽 Result 預估全季 +150–200 KB（gzip 約 40 KB），單獨成 chunk。既有的「data chunk 不得超過 X」若有測試，門檻不變，只對主要 chunk 計。

## Testing Decisions

### 什麼是好的測試

同規格書 0001：只測外部可觀察的行為，以「給定這些資料與這個時間點，使用者會看到什麼」描述。

### 接縫

沿用**既有的主要接縫**，不新增：

> **`原始 API fixtures + 指定的「現在時間」  →  Snapshot  →  View Model`**

本規格的所有行為都落在這條接縫上：

- **Session Result 正規化**：OpenF1 session_result fixture → Snapshot 的 Session.result；車號對縮寫、對不到的車號保留、DNF／DNS 的 Best Lap 為 null、衝刺週末的場次對照。
- **預設籤**：不同「現在時間」下 `latestFinishedSession` 的值——週五 FP1 後、週六排位後、週日正賽後、全部未開始、Off-season。
- **Result 格式化**：Best Lap `1:23.008`、Gap `+0.442`、無成績旗標、排位賽淘汰節次的欄位為 null。
- **Driver 資歷**：`debutSeason` 與現在季推出「第 N 季」；本季出道的特例；跨年後自動 +1（用 2027 的注入時間）。
- **年齡**：生日前一天與當天的邊界。
- **Circuit 總里程**：長度 × 圈數。
- **Breadcrumb 段落鏈**：每個路由型態產生的段落與連結；譯名缺席時的英文備援；首頁為空。與既有的 `routesFor` 測試同一風格——掃描全部路由，確保沒有路由型態漏產生段落鏈。
- **Profile 資料完整性**：Profile 的每個鍵都對到本季存在的實體（失敗）；本季實體缺 Profile 時列出清單（警告）；國籍對照缺席（失敗）。與既有的譯名表覆蓋測試同一風格。
- **快照 carry-forward**：OpenF1 失敗時 result 沿用舊快照，與既有代表色 carry-forward 測試同一風格。

### Fixtures

新增 OpenF1 sessions 與 session_result 的真實回應錄製（一般週末一份、衝刺週末一份），以及 Jolpica `results?limit=1` 的一筆。既有 Snapshot fixture 補上 `dateOfBirth`、`debutSeason` 與各場次 `result`。**不在測試中打真實網路。**

### 不測的

- 分頁籤的鍵盤操作與 ARIA（瀏覽器行為，手動驗證一次）。
- Favicon 的像素內容（建置腳本產出即可，以檔案存在與尺寸為驗收）。
- Breadcrumb 的截斷樣式。

## Out of Scope

- **練習賽的逐圈資料、輪胎配方、長距離模擬分析**。OpenF1 有 laps 與 stints，但需要另一層彙整邏輯與數倍的快照體積；本批只做名次表。
- **排位賽改用 OpenF1**。Jolpica 已足夠且已在快照中；兩個來源會帶來對帳問題。
- **車手生涯總勝場、總積分、總桿位**。需翻整個生涯賽果（每人多頁請求），每週抓取變慢且易撞速率限制。
- **車隊首次參賽年、歷年冠軍數**。Audi／Cadillac 等新隊的「前身」定義有歧義，且沒有 API。
- **賽道首次舉辦年、彎角命名**。無 API，逐條手寫的價值低於簡介文字。
- **Profile 從維基百科自動抓取**（使用者決策：純手寫）。
- **Breadcrumb 的結構化資料（JSON-LD）**。本站無 SEO 目標。
- **分頁籤狀態寫進網址**。會新增路由型態，牽動預產生清單，且分享單一場次結果的需求尚未出現。
