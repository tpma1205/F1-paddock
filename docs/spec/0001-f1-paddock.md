# 規格書：F1 Paddock

> 狀態：待實作 ｜ 語彙依據：[CONTEXT.md](../../CONTEXT.md) ｜ 決策依據：[ADR-0001](../adr/0001-hybrid-snapshot-data-strategy.md) ~ [ADR-0004](../adr/0004-auto-rolling-season-with-archive.md)

## Problem Statement

身為華語圈的 F1 觀眾，我想知道的事情散落在各處：官網是全英文且資訊密度高、中文報導多半只寫賽後結果、賽程時間全是 UTC 或賽道當地時間，要換算成自己的時區才知道幾點要守在電視前。想快速確認「下一場什麼時候開始」「現在誰領先」「這條賽道長什麼樣」，往往得開三四個分頁拼湊。

更麻煩的是，多數中文 F1 資訊站的內容是人工整理的，賽季一過就沒人維護，隔年再打開已是舊資料；而純英文的官方來源雖然即時，車手與車隊名稱卻沒有中文對照，對剛入坑的人門檻很高。

## Solution

一個以黑色為主視覺、可在手機與桌機上使用的 F1 資訊網站，把當前球季的賽程、積分、車隊、車手與賽道整合在同一處，中英名稱並陳，所有時間自動換算成使用者所在時區。

網站的資料來自公開 API，並由排程自動更新，**不需要人工維護內容**；跨年時會自動遞延到新球季，舊球季則逐年封存供回看。首頁是一段可滾動瀏覽的敘事，開頭即是指向 Next Session 的大型倒數與該 Race Weekend 的完整場次表；往下依序帶出本季戰況、車隊、車手與賽道，想細看再點進各自的內頁。

## User Stories

### 首頁儀表板

1. 作為一個想知道何時開賽的觀眾，我想在首頁最上方看到指向 Next Session 的大型倒數，這樣我不必點任何連結就能得到最想要的答案。
2. 作為一個觀眾，我想讓倒數明確標示它指的是哪一個 Session（FP1／排位賽／正賽），這樣我不會誤把練習賽的時間當成正賽。
3. 作為一個觀眾，我想在 Session 開始後看到倒數自動跳到下一個 Session，這樣我不需要重新整理頁面就能持續得到正確資訊。
4. 作為一個觀眾，我想在某個 Session 正在進行時看到「進行中」而非負數倒數，這樣畫面在最關鍵的時刻不會顯得壞掉。
5. 作為一個觀眾，我想看到本週末**每一個** Session 的星期與時間，這樣我可以安排整個週末的收看計畫。
6. 作為一個觀眾，我想讓已結束的 Session 在視覺上變暗、Next Session 高亮，這樣我一眼就知道進度到哪裡。
7. 作為一個觀眾，我想在 Sprint Weekend 看到衝刺排位與衝刺賽取代 FP2／FP3，這樣場次表反映的是真實賽制而不是固定樣板。
8. 作為一個觀眾，我想看到當前 Race Weekend 的國旗、中英文名稱與 Round 編號，這樣我知道現在講的是哪一站。
9. 作為一個身處任何時區的使用者，我想看到已換算成我所在時區的時間，並清楚標示是哪個時區，這樣我不會因為預設時區而算錯。
10. 作為一個觀眾，我想在首頁往下滾時看到本季戰況（車手與車隊積分榜前幾名），這樣我不必進內頁就掌握大勢。
11. 作為一個觀眾，我想在首頁看到車隊、車手、賽道的橫向預覽與「查看全部」入口，這樣首頁能導覽而不必承載全部內容。
12. 作為一個觀眾，我想知道畫面上的資料是什麼時候更新的，這樣我可以判斷它有多新。
13. 作為一個在 Off-season 造訪的觀眾，我想看到距離下一季開幕的倒數與本季回顧，這樣網站在空窗期依然有內容。

### 車隊

14. 作為一個觀眾，我想看到本季所有 Team 的列表，包含 logo、英文名稱、中文名稱與積分，這樣我能快速比較各隊實力。
15. 作為一個觀眾，我想讓每支 Team 以自己的代表色呈現，這樣我能靠顏色而非閱讀來辨識車隊。
16. 作為一個觀眾，我想在某支 Team 的 logo 無法載入時仍看到得體的字標而非破圖，這樣畫面不會因外部資源失效而崩壞。
17. 作為一個觀眾，我想點進 Team 詳情頁看到該隊兩位 Driver、累計積分、勝場與名次，這樣我對這支車隊有完整認識。
18. 作為一個觀眾，我想看到 Team 的中文名稱採用台灣慣用譯名，這樣讀起來符合我的語言習慣。

### 車手

19. 作為一個觀眾，我想看到本季所有 Driver 的列表，包含照片、英文名稱、中文名稱與積分，這樣我能認識整個車手陣容。
20. 作為一個觀眾，我想看到每位 Driver 所屬的 Team 與車號，這樣我在轉播中看到車號時能對上人。
21. 作為一個觀眾，我想在 Driver 照片無法載入時看到以車隊代表色與姓名縮寫組成的替代圖，這樣列表的視覺節奏不會被破壞。
22. 作為一個觀眾，我想點進 Driver 詳情頁看到本季積分、勝場、頒獎台與名次走勢，這樣我了解他這季的表現。
23. 作為一個新入坑的觀眾，我想看到暫無公認譯名的新人 Driver 被標示為暫定譯名，這樣我知道那不是官方定名。
24. 作為一個觀眾，我想把 Driver 頁面的網址分享給朋友，讓對方直接開啟該車手頁面，這樣分享是有意義的。

### 賽道

25. 作為一個觀眾，我想看到本季所有 Circuit 的列表與中英文名稱，這樣我知道這季會去哪些地方。
26. 作為一個觀眾，我想在 Circuit 詳情頁看到清晰的賽道平面圖，這樣我能理解賽道的形狀與特性。
27. 作為一個觀眾，我想看到賽道平面圖隨著我的滾動一筆畫出來，這樣瀏覽過程本身是愉快的。
28. 作為一個觀眾，我想看到 Circuit 的長度、海拔、彎道數、比賽圈數與單圈紀錄，這樣我對這條賽道有量化的認識。
29. 作為一個手機使用者，我想能放大檢視賽道平面圖，這樣小螢幕不會讓圖形失去意義。
30. 作為一個觀眾，我想看到 Circuit 與它所屬 Race Weekend 的相互連結，這樣我能在「地點」與「賽事」之間來回。

### 賽程與賽果

31. 作為一個觀眾，我想看到本季完整的 23 站賽程表，這樣我能規劃整季的收看。
32. 作為一個觀眾，我想在賽程表上區分已完賽與未來的 Race Weekend，這樣我一眼看出賽季進度。
33. 作為一個觀眾，我想在已完賽的站次上直接看到前三名，這樣我不必點進去就知道結果。
34. 作為一個觀眾，我想點進單站看到完整 Result，包含名次、車手、車隊、積分與退賽狀態，這樣我掌握該場全貌。
35. 作為一個觀眾，我想把整季賽程匯出成行事曆檔案加進我的日曆，這樣離開網站後我依然會被提醒。
36. 作為一個觀眾，我想匯出的行事曆事件使用正確的時區資訊，這樣它在我的手機上顯示的時間是對的。

### 加值分析

37. 作為一個 F1 迷，我想看到同隊兩位 Driver 的積分、勝場與排位對戰比較，這樣我能判斷誰是隊上更強的一方。
38. 作為一個觀眾，我想看到積分隨 Round 累積的走勢圖，這樣我看得出賽季是在哪一站翻盤的。
39. 作為一個觀眾，我想看到本季數據亮點（最多勝、最多桿位、最多頒獎台、退賽次數），這樣我快速獲得談資。

### 跨球季

40. 作為一個明年還會回來的使用者，我想讓網站在跨年後自動呈現新球季，這樣我不需要任何人去更新它。
41. 作為一個在新球季開賽前造訪的使用者，我想看到上一季的最終積分並明確標示年份，這樣畫面不會空白兩個月。
42. 作為一個長期使用者，我想能回看已封存的舊球季，這樣這個網站會隨時間累積價值。

### 體驗與可及性

43. 作為一個手機使用者，我想在窄螢幕上看到為小螢幕設計的版型而非被壓縮的桌機版，這樣「掏出手機瞄一眼」的情境真的可用。
44. 作為一個對動態敏感或開啟系統減少動畫設定的使用者，我想讓網站自動降低動畫強度，這樣我不會感到不適。
45. 作為一個網路較慢的使用者，我想在資料還沒更新完成前就先看到完整畫面，這樣我不必盯著載入動畫等待。
46. 作為一個在 API 故障期間造訪的使用者，我想仍然看到完整的網站內容並被告知資料可能不是最新，這樣網站不會整個失效。
47. 作為一個直接開啟內頁網址或按重新整理的使用者，我想正常看到該頁面而非 404，這樣網址是可信賴的。

## Implementation Decisions

### 整體形狀

- 純前端靜態網站，**無後端**。三個資料來源（Jolpica-F1、OpenF1、f1-circuits GeoJSON）皆免金鑰且 CORS 全開，已實測確認。
- 技術棧為 **Vite + React + TypeScript**。TypeScript 為必要而非偏好：兩個第三方 API 的 JSON 巢狀且不直覺，需要在型別層把**外部原始形狀**與**內部檢視模型**明確分離。
- 動畫使用 **Framer Motion**（`whileInView` 處理進場、`useScroll` 處理 scrub）。不採用 GSAP ScrollTrigger，因其強項在釘住式 scrollytelling，而該手法已被明確排除。

### 資料管線

管線為三段，**每段的產物都是可獨立檢視的資料**：

```
原始 API 回應  ──normalize──►  Snapshot  ──derive──►  View Model  ──►  UI
  (第三方形狀)                 (內部形狀)     (含「現在時間」)       (純呈現)
```

- **Snapshot** 是內部正規化形狀，以 `season` 為索引鍵組織（見 ADR-0004）。它同時是建置產物與開發基準。
- **View Model** 是一個純函式的輸出：輸入 Snapshot 與「現在時間」，輸出畫面所需的一切（Next Session、各 Session 狀態、積分榜、隊友對決、數據亮點、應存在的路由清單）。**所有與時間相關的推導都集中在此，元件本身不做時間判斷。**
- UI 元件僅負責呈現 View Model，不含業務邏輯。

### 資料取得與更新

- 採**快照打底 + 執行期背景更新**（ADR-0001）：打包的 Snapshot 立即渲染，載入後於背景重新抓取，成功才替換，並於畫面標示資料時間。
- UI 必須能表達「來自快照」與「已更新」兩種狀態，不得假裝資料永遠即時。
- 抓取腳本**一律使用 Jolpica 的 `/current/` 端點，不得寫死年份**（ADR-0004）。
- 更新由 GitHub Actions 每週二排程執行（抓取 → 建置 → 部署），另掛手動觸發。**抓取失敗時沿用既有快照繼續建置**，不讓第三方故障造成部署失敗。
- 已知 API 限制：Jolpica 的跨球季查詢強制要求 `season_year`，無法一次取得歷年資料。任何跨球季功能都須先評估請求次數。

### 路由與部署

- 部署至 GitHub Pages，repo 名 `F1-paddock`，Vite `base` 為 `/F1-paddock/`（ADR-0002）。
- 使用 BrowserRouter；**建置期依 Snapshot 產生每個已知路由的實體 HTML**（約 60 個），使靜態伺服器真的找得到檔案。另備 `404.html` 作為安全網。
- **路由清單由 View Model 提供**，而非在建置腳本中另行硬編。這是為了讓「新增路由型態卻忘記更新產生腳本」這個 ADR-0002 已知陷阱能被測試守住。
- 路由帶 `season` 維度（如 `/2026/drivers/antonelli`），當前球季可省略年份。

### 呈現與語言

- 雙語規則：**專有名詞**（Team／Driver／Circuit／Race Weekend）為英文大字 + 中文小字；**Interface Copy** 一律繁體中文，不做雙語並陳。
- 中文採**台灣慣用譯名**；無公認譯名者標記為 **Provisional Name**。
- 中文對照表為專案唯一的手工資產（約 80 筆），與賽道的彎道數／圈數／單圈紀錄同表維護。**它是靜態資料而非抓取結果，必須進版控。**
- 時區以瀏覽器 `Intl` 偵測，並在畫面明確標示時區名稱與偏移。

### 視覺系統

- 黑色採**分層深灰**（底 `#0A0A0C`／卡片 `#141418`／浮起 `#1E1E24`），不使用純黑，以保留視差與滾動特效所需的層次。
- **配色分層**：F1 紅 `#E10600` 為網站骨幹（導覽、倒數、狀態、進度條）；**Team 代表色為內容身分**（卡片色條、logo 光暈、對比條、賽道描邊），兩者不重疊。
- Team 代表色取自 OpenF1 `team_colour`。**低對比色（如 Cadillac `#909090`、Red Bull `#4781D7`）作為文字使用時須自動提亮**，作為圖形裝飾時保留原色。
- 字體：Titillium Web（英文與數字）+ Noto Sans TC（中文）。
- 動畫一律以 `transform`／`opacity` 實作；尊重 `prefers-reduced-motion`；窄螢幕自動關閉視差，保留淡入與交錯進場。

### 圖片

- 所有第三方圖片**一律熱連結、不進 repo**（ADR-0003）。
- Driver 照片使用 OpenF1 `headshot_url`；Team logo 熱連結官方 9 隊，**Audi 與 Cadillac 使用自製字標**（官方 CDN 查無檔案）。
- 所有 logo 渲染進**同一固定尺寸容器**並施以統一的代表色處理，使兩張自製字標讀為設計節奏而非破圖。
- 每個外部圖片都須有 `onError` 降級路徑，此為常態機制而非例外處理。
- Circuit 平面圖由 f1-circuits GeoJSON 的 LineString 轉為 SVG path 自繪（MIT 授權，**唯一可合法納入 repo 的圖像素材**），並以 `stroke-dashoffset` 實作隨滾動描繪。

## Testing Decisions

### 什麼是好的測試

只測**外部可觀察的行為**，不測實作細節。測試應該描述「給定這些資料與這個時間點，使用者會看到什麼」，而不是「某個函式被呼叫了幾次」。重構內部結構時測試不該壞；行為改變時測試必須壞。

### 主要接縫（Seam）

專案為全新建置，尚無既有接縫可用。提議**單一主要接縫**：

> **`原始 API fixtures + 指定的「現在時間」  →  View Model`**

理由：

- 這是能涵蓋最多行為的**最高**接縫。normalize 與 derive 兩段都在其中，卻不需要啟動瀏覽器或渲染任何元件。
- 它讓「現在時間」成為**顯式輸入而非環境狀態**，這對本專案至關重要——Next Session 推導、Session 狀態、Off-season 降級、跨年遞延（ADR-0004 明確指出「本地測試無法直接驗證換季行為」）全都依賴時間，而這些情境在真實世界一年只出現一次。
- 中介產物 Snapshot 在同一接縫上可被斷言，因此第三方 API 形狀變動仍能被定位，不會只得到一個模糊的失敗。

### 涵蓋的行為

- **Next Session 推導**：一般週末、Sprint Weekend、某 Session 進行中、當日最後一個 Session 結束後跨到隔天、正賽結束後跨到下一個 Round。
- **Session 狀態標記**：已結束／進行中／未開始的分界，特別是邊界時刻。
- **Sprint Weekend**：場次組成由資料決定，FP2／FP3 缺席時不得出現空欄位。
- **Off-season 與換季**：本季結束後指向下季開幕；`current` 已遞延但新季無 standings 時，積分區塊回退為上季最終並標示年份。
- **時區換算**：同一份 Snapshot 在不同時區下產生正確的當地時間與星期。
- **降級路徑**：缺少 `headshot_url`、缺少 Team logo、缺少某 Circuit 的 GeoJSON 時，View Model 仍完整且標記出替代方案。
- **路由清單**：View Model 產出的路由涵蓋所有 Team／Driver／Circuit／Round，是建置期產生實體 HTML 的唯一依據。

### Fixtures

以真實 API 回應錄製為 fixture 並進版控，至少涵蓋：一般週末、Sprint Weekend、季末最後一站、以及一份新球季僅有賽程而無 standings 的情境。**不在測試中打真實網路。**

### 次要接縫

僅在主要接縫無法涵蓋時才增加，且須先討論。目前預期只有兩處可能需要：GeoJSON 座標轉 SVG path 的幾何轉換（純函式，易測且易錯），以及行事曆檔案的產出格式（有外部格式規範需符合）。**元件層渲染測試不納入**——其行為已由 View Model 決定，於元件層重測只會得到高維護成本與低訊號。

## Out of Scope

- **即時比賽模式**（OpenF1 即時圈速、位置、車間距）。僅在 Session 進行中的數小時有資料，且需引入輪詢與重連狀態機，投入產出比不成立。
- **歷年冠軍列表與完整歷史瀏覽**（1950–）。Jolpica 強制 `season_year`，需 76+ 次請求打一個志工營運的免費服務；且早期車手無照片、老賽道 GeoJSON 不齊。
- **賽道即時天氣**。同即時模式，平時無資料。
- **一次性支援多個歷史球季**。改採 ADR-0004 的逐年封存，價值相同但成本分攤且不需回補譯名。
- **使用者帳號、收藏、通知、留言**。本站無後端，這些都需要引入伺服器。
- **釘住式（pinned）橫向滾動與全螢幕接管開場**。與「首頁精華、內頁查閱」的動線衝突，且在觸控裝置上易造成挫折。
