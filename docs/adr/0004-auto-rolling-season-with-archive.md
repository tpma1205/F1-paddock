# 球季自動遞延，舊季逐年封存

網站永遠呈現當前球季，且**不在任何地方寫死年份**。抓取腳本一律使用 Jolpica 的 `/current/` 動態端點（實測可用，現回傳 2026 R13），搭配 ADR-0001 的每週排程，跨年時網站會自行換季，無需人工介入。資料模型與路由皆以 `season` 為索引鍵（`snapshot/<season>/…`、`/<season>/drivers`），首頁預設指向當前球季。

換季時工作流程會將上一季的完整快照凍結並 commit 進 repo 一次，成為永久封存。ADR-0001「不 commit 回 repo」原則只有兩個例外：**剛結束的球季**（首次進入已結束狀態時封存一次；之後每週抓取只改到 `fetchedAt`，不再 commit）與**首次出現的下一季賽程**（沒有它，換季後的第一次建置就沒有賽程可用）。

## 換季邊界的陷阱

跨年當下 `/current/` 已指向新球季，但**新球季的積分榜是空的**（尚未開賽）。若不處理，積分榜、隊友對決、積分走勢圖會從 1 月空白到 3 月開季，長達兩個多月。

處理方式：當前球季尚無 standings 時，積分相關區塊改顯示**上一季的最終結果並明確標示年份**（例如「2026 最終」），賽程與倒數則指向新球季；新球季首站結束後自動切回即時資料。

## Consequences

- 「當前球季」是由 API 而非設定檔決定的，**本地測試無法直接驗證換季行為**。相關邏輯需可注入模擬日期與模擬回應。
- 封存採「當年維護、逐年累積」而非「事後回補」，因此**中文對照表不需要回頭補譯已退役車手**——這正是逐年封存優於一次性支援多季的關鍵。
- 每年會出現一次機器人 commit（封存用），屬預期行為。

## 實作（票 13）：賽程季與積分季分開選擇

`buildViewModel` 接收**所有球季**的快照，依注入的時間決定兩件事：

- **賽程季** = 最舊的「尚未結束」的球季。球季進行中即為本季（下一季賽程已公布也不提前切換）；本季最後一場結束後自動變成下一季；全部結束時退回最新一季並進入 Off-season。
- **積分季** = 賽程季本身有積分就用它，否則回退到最近一個有積分的舊球季，畫面標示「該年 賽季 · 最終積分」。積分、車隊、車手、走勢、亮點、隊友對決全部跟著積分季；賽程、倒數、賽道跟著賽程季。

抓取腳本在寫完本季後**主動探測下一季賽程**（年份由本季推算），已公布就寫一份只有賽程的快照——這讓 Off-season 的首頁能倒數到下一季開幕，而非等 `/current/` 在跨年時才跳。

換季行為全部以注入時間 + 合成的下一季快照測試；另有一條測試掃描全部產品程式碼，確認沒有寫死的四位數年份（CDN 資產目錄是唯一登記的例外）。
