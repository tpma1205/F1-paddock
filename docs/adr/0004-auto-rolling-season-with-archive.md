# 球季自動遞延，舊季逐年封存

網站永遠呈現當前球季，且**不在任何地方寫死年份**。抓取腳本一律使用 Jolpica 的 `/current/` 動態端點（實測可用，現回傳 2026 R13），搭配 ADR-0001 的每週排程，跨年時網站會自行換季，無需人工介入。資料模型與路由皆以 `season` 為索引鍵（`snapshot/<season>/…`、`/<season>/drivers`），首頁預設指向當前球季。

換季時工作流程會將上一季的完整快照凍結並 commit 進 repo 一次，成為永久封存。這是 ADR-0001「不 commit 回 repo」原則的唯一例外。

## 換季邊界的陷阱

跨年當下 `/current/` 已指向新球季，但**新球季的積分榜是空的**（尚未開賽）。若不處理，積分榜、隊友對決、積分走勢圖會從 1 月空白到 3 月開季，長達兩個多月。

處理方式：當前球季尚無 standings 時，積分相關區塊改顯示**上一季的最終結果並明確標示年份**（例如「2026 最終」），賽程與倒數則指向新球季；新球季首站結束後自動切回即時資料。

## Consequences

- 「當前球季」是由 API 而非設定檔決定的，**本地測試無法直接驗證換季行為**。相關邏輯需可注入模擬日期與模擬回應。
- 封存採「當年維護、逐年累積」而非「事後回補」，因此**中文對照表不需要回頭補譯已退役車手**——這正是逐年封存優於一次性支援多季的關鍵。
- 每年會出現一次機器人 commit（封存用），屬預期行為。
