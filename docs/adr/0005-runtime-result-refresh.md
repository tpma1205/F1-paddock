# 以「立即更新」按鈕在執行期補抓剛結束場次的結果

ADR 0001 原本的混合策略是「快照打底 + 載入後背景更新」，但背景更新從未實作，畫面只有打包的快照，最快也要等下一次排程（每天，比賽週末每 3 小時）才看得到剛結束的場次。我們補上它，但**不做自動背景輪詢**：使用者按下頁尾的「立即更新」，才針對「已結束、快照裡還沒有結果」的場次向 API 補資料，結果只存在當下瀏覽器的記憶體裡。

## 決策

- **只補缺的場次。** 「已結束」由開始時間加固定時長判斷（`RESULT_DUE_MINUTES`：練習賽、衝刺排位、衝刺賽 90 分鐘，排位賽 120 分鐘，正賽 210 分鐘）。這與只驅動「進行中／已結束」顯示的 `SESSION_DURATION_MINUTES` 刻意分開：這裡要的是「值得去問 API 的時間點」，偏保守，紅旗拖長的正賽才不會被誤判。只看**最近一個有到期場次的賽事週末**，一次最多 3 個場次，優先序為正賽、排位賽、衝刺賽、衝刺排位、練習賽。
- **來源分工不變，加上暫定結果。** 排位賽、衝刺賽、正賽先問 Jolpica；Jolpica 還沒有，才用 OpenF1 `session_result` 產生**暫定結果（Provisional Result）**。FP1–3 與衝刺排位只有 OpenF1。積分榜只從 Jolpica 取。
- **請求預算。** 依序（不並行）送出，單次上限 10 次：Jolpica 結果 ≤ 3、積分榜 2、OpenF1（場次清單 1、車手 1、名次 ≤ 3）。60 秒冷卻；沒有待補場次時不發請求也不計冷卻。
- **更新只放記憶體。** 不寫回 repo、不進 `localStorage`。重新整理就回到打包快照，使用者再按一次。放棄持久化是為了避開過期問題：本機存的資料與新部署的快照誰覆蓋誰、暫定結果被正式結果取代時如何比版本。
- **積分榜不推算。** 只在取得正式的衝刺賽／正賽結果、或積分榜站次本來就落後時才抓。Jolpica 回應的 `round` 小於已有正賽結果的最大站次，就**丟棄**並顯示「積分榜尚未更新」，維持舊資料。判斷站次用 Snapshot 既有的 `completedRound`（即積分榜的站次），不另加欄位。
- **頁尾「資料更新於」只在真的補到新資料時才變。** 失敗與沒有新資料時保持不變，另在狀態行顯示「上次檢查」時間，讓使用者知道按鈕確實有執行。這延續 ADR 0001「不可假裝資料永遠是即時的」。
- **OpenF1 回 401 不是錯誤。** 場次直播期間 OpenF1 封鎖所有未認證請求（連歷史資料）。畫面顯示「場次進行中，結束後才能取得結果」，與一般錯誤、「來源尚無資料」、「沒有待補場次」的訊息彼此不同。

## 暫定結果的取捨

暫定結果是獨立型別 `ProvisionalResult`，**不**塞進 `RaceResult`。`RaceResult` 的積分、起跑格、最速圈、狀態字串都是必填，若沿用它就得填假值（例如 `points: 0`），而 `0` 與「不知道」在畫面上無法分辨。暫定結果只含 OpenF1 實際提供的欄位：名次、車號、車手、車隊、圈數、結果（完賽／退賽／未起跑／失格）、總時間或差距、排位賽的 Q1–Q3。缺的欄位在畫面顯示「—」。

- **車隊**取自該車手在快照積分榜上的車隊，不用 OpenF1 的 `team_name`（與 Jolpica 的 `constructorId` 對不上，ADR 0003 已記錄）。對不到的車手（青年車手、年中轉隊）車隊留空，不猜。
- **畫面可分辨。** 暫定結果有虛線「暫定」標籤與說明；正式結果一到，同場次的暫定結果就被移除。暫定結果不進積分走勢、隊友對決與數據亮點——那些統計只認正式結果。
- 場次面板的第一名在沒有正式結果時，由暫定結果補上。

## 已知的限制

- **OpenF1 排位賽、衝刺賽、正賽的 `session_result` 欄位格式未實測。** 寫作時 OpenF1 正在直播、對所有請求回 401。轉換邏輯依練習賽與衝刺排位的實測格式與 OpenF1 文件推得：排位賽的 `duration` 為三節陣列，正賽的 `duration` 為秒數、`gap_to_leader` 為秒數或落圈字串。測試的 fixtures 是依此推得的，**不是錄製的真實回應**。場次結束後應補驗並以錄製的回應取代 fixtures。
- 排程只縮短「不按按鈕也看得到」的等待，不是即時。`deploy.yml` 在比賽週末（UTC 週五～週一）新增每 3 小時一次的排程，分鐘數用 43，避開整點（實測 `0 2` 會被 GitHub 排程延遲五小時）。
- 使用者要看到暫定結果，必須主動按按鈕；沒有按的人看到的仍是打包的快照。

## Considered Options

- **載入後自動背景輪詢（ADR 0001 原案）：**使用者不必動作，但每個訪客都會打 API，OpenF1 未認證上限約每分鐘 30 次，直播期間更是全擋。
- **只靠加密排程：**不增加前端複雜度，但最快仍要等數小時，無法解決「場次剛結束想立刻看」的需求。
- **把暫定結果塞進 `RaceResult`，缺的欄位填 0：**畫面程式最少，但會讓暫定積分看起來像真的。
- **更新後存進 `localStorage`：**重新整理後仍保留，但要處理過期與合併，價值不足。
